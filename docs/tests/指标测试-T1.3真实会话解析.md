# 指标测试 — T1.3 真实宿主会话解析

状态: 已实测（2026-09-22） | 对应: DEVELOPMENT-PLAN §5 M1 第 5 项、FR-A1、T1.3 | 关联: ADR-0016

## 目的

兑现 M1 出口新增的那一条硬验收：**对本机真实宿主会话跑 `discover` + `parse`，如实记录
行级去向分布**，而不是只用合成 fixture 与测试语言自证。这一项存在的理由是
`collectors.md` 的判断——格式漂移的第一信号是计数异常，不是崩溃；而"计数异常"能不能被
相信，取决于基线是否干净。

## 步骤

1. 用包 API（不是测试替身）对真实源根跑 `ClaudeAdapter.discover()`；
2. 对每个 `SessionRef` 完整 `parse()`，逐文件累计 `ParseStats`；
3. 只输出聚合计数与原因分布：文件身份以 `sha256(文件名)[:8]` 表示，
   **不打印 prompt 原文、命令原文、真实绝对路径**（AGENTS §4.3 第 4 条、REPO-LAYOUT §3）；
4. 原始解析结果不落仓库、不 commit（脚本与输出都在 gitignored 的 `.aftermatter/` 下）。

复现命令（本机，仓库根）：

```
uv run python .aftermatter/real-parse.py
```

## 结论

1. **对应 M1 第 5 项：通过。** 真实会话被 `discover` 全量收进（11/11），被 `parse` 无异常
   跑完（0 失败），且 `unparsed = 0` —— 说明 `IGNORED_TYPES` 清单覆盖了这批真实样本里全部
   非会话事件，"格式漂移第一信号"目前是一条干净的零基线。这正是把 `ignored` 与
   `unparsed` 拆开的目的：若不拆，40.86% 的行会被算成漂移，信号永久失效。
2. **`tool_call` 90 与 `tool_result` 91 不等**，与探雷阶段的实测一致：会话里存在孤儿结果
   （跨文件续接或中断所致）。因此 T1.6 的"验证配对"逻辑不得假设严格成对。
3. **`lifecycle` / `permission_decision` / `hook_event` 在真实样本里为 0。** 这三类 kind 目前
   只有合成 fixture 覆盖（`system_subtype` 25 行全部不是 `compact_boundary`，故未产出
   lifecycle 事件）。诚实标注：**这三个 kind 尚无真实宿主证据**，映射规则待有真实样本的
   机器/版本上再复核，不能宣称已被实测验证。
4. **样本局限**：单台机器、单一宿主（Claude Code）、964 KB / 465 行，且全部来自近一周的
   本机使用；不构成对宿主全版本矩阵或跨用户形态的覆盖。`outside_path_count = 7` 说明
   会话确实会触达仓库外路径，`target_paths` 的越界丢弃策略在真实数据上有作用。
5. 本文件只做记录，不改动契约；`reasons` 键全部经 `safe_reason` 净化，实测输出中无路径分隔符。
