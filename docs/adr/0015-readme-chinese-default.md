# ADR-0015: 门面 README 默认中文，英文版镜像

状态: Accepted | 日期: 2026-09-22
Related: ADR-0011 文档语言分层与写作规范（局部修订其决定 1）、ADR-0013 docs/tests/ 中文文件名豁免、
[REPO-LAYOUT.md](../REPO-LAYOUT.md) 的「§1 顶层布局」、PRD 的「§10 R4 与原版功能撞车被比较」

## 背景

维护者裁决：仓库根 `README.md` 以**中文为默认门面**，另提供英文版。这与 ADR-0011 决定 1
"门面文档用英文"直接冲突，且 `REPO-LAYOUT.md` §1 原本预留的是 `README.zh-CN.md`（中文附加版），
方向相反。裁决依据是开发期获客事实：项目冷启动的第一批读者与贡献者来自中文技术社区，
首屏语言决定停留；而 Star/参与转化发生在"第一眼读懂它在解决我的什么问题"那一刻。

## 决定

1. **`README.md` = 中文门面**（GitHub 默认落地页），**`README.en.md` = 英文镜像版**；
   两份文件首屏互链，结构、事实、数字必须一致，不允许一份先长大。
2. **取消 `README.zh-CN.md` 预留**：从未使用，且与新方向语义相反；`REPO-LAYOUT.md` §1 同步改写。
3. **其余门面文件保持英文**：`CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md` 是流程与法务文本，
   面向国际贡献者的成本更低，翻译只会增加双写漂移，不获客。
4. **代码与提交规范不变**：标识符英文、commit message 英文 Conventional Commits、
   `AGENTS.md`/`CLAUDE.md` 双语镜像例外照旧（ADR-0011 决定 1 未整体推翻，只改门面这一格）。
5. **品牌图与架构图分开处置**：`docs/assets/` 下的 logo 与 hero 由生成模型产出，**只承载视觉**；
   架构与数据流一律用 Mermaid/ASCII 写在文档里。生成式位图无法保证标签正确，
   让一张拼写错误的架构图进仓库，比不配图更伤可信度。
6. 双语同步目前由评审人工保证，不机器化（校验"两份 README 结构一致"没有稳定的判定标准，
   写出来只会得到一条脆弱断言）。

## 影响

- `README.md` 重写为中文门面版；新增 `README.en.md`；
- `docs/assets/` 收纳品牌图（README 首屏当前用 wordmark 横幅）；图片体积不受门禁抠字节约束，
  `check-added-large-files` 阈值放宽到 2048 KB，只为拦住误提交的会话 dump 与模型文件；
- 同步修订：ADR-0011 决定 1 加括注、`docs/README.md` 语言分层表"门面"行、
  `REPO-LAYOUT.md` §1 顶层布局行、`CONTRIBUTING.md` 的 Language 段；
- PRD §10-R4 要求"差异化主张进 README 首屏 + 承认灵感来源并给贡献路径"：中文门面版首屏
  即放差异化四条与 Better Harness 溯源声明，措辞受 dual-brain spec §3 与 ADR-0009 校准口径约束
  （禁说"原版没有修复闭环/没有实验系统"）；
- 本仓库文档语言分层从此为：门面 README 中文（英文镜像）｜其余门面与用户向英文｜内部设计中文。

## 被否备选

- **保持英文门面 + `README.zh-CN.md` 中文版**：与用户裁决相反，中文读者首屏仍是英文，
  冷启动停留率损失最大；且等于把"默认"让给英文。
- **README 三份语言（+ 日文等）**：单人项目维护不动，翻译会先于功能过期（ADR-0011 已否过全量双语）。
- **门面全改英文、内部设计也改英文**：撰写精度与速度双损，核心读者是自己与中文宿主。
- **用生成模型画架构图**：文字与结构不可控，产出的"看起来对"的图会直接违背项目的证据诚实红线。
- **把双语 README 一致性写进 doc-lint**：可校验的只有"文件存在"，结构对齐无法稳定判定，
  属于用假门禁换心安。
