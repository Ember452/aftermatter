# 双大脑形态与三项深化：立项决策全论证

日期: 2026-09-21 | 状态: accepted（ADR-0003/0004/0005 的完整背景件）

## 1. 决策清单（本文覆盖）

| 决策 | 结论 |
|------|------|
| 项目性质 | 独立新项目（与 FlowCoder/KnowFlow 资产解耦），目标求职 + GitHub 开源 |
| 证据源 | 编码 Agent 本地会话（Claude Code/Codex/Cursor/Qoder JSONL）+ 仓库证据 |
| 核心主张 | 闭环到"修复 + 纵向验证"（原版止步于人驱动流程） |
| 形态 | 双大脑（ADR-0003）：寄生宿主 + 自带 LLM 引擎，同契约可插拔 |
| 深化三项 | A 准因果纵向验证 / B 执行级证据引擎 / C 反幻觉反作弊体系 |
| 隐私边界 | 本地采集与分析，只上传脱敏 findings；服务端只管账号/团队/趋势/存档 |
| Inspector | 只预埋机制不做 UI（ADR-0005） |

## 2. 竞品源码级证据（全部实测，非文档转述）

1. **原版零 LLM 调用**：对其安装缓存全仓 grep `api.openai|api.anthropic|chat/completions|x-api-key|fetch(` 零命中。
   其"智能"完全由宿主 Agent 按 SKILL.md 执行——这决定了它无法无人值守、无法自动复验。
2. **Episode 契约可抄之处**（episode-contract.mjs 源码）：30min 时间缺口切分、
   事件自带 evidenceRefs 指针、验证事件靠命令模式识别（test/lint/build）、
   权限拒绝与 hook-block 计为摩擦信号、自身产物路径从证据中剔除（防自污染）。
3. **架构图第⑥段 Repair→Validate→Record 存在**：原版有闭环"概念"，
   但执行靠宿主会话中的人驱动（finding-bound fix 流程），验证无复跑机制。
4. **History 视图仅一行免责声明**（"not causal proof"）：有趋势展示，
   无匹配/混杂/统计机制——F4 与深化 A 的空位由此确认。
5. **命名带已被占**：proofloop（含 CI 门禁质量插件）、reverify（942★）、
   groundproof（声称-事实核验）、retroscope——佐证"证据+验证 agent"赛道升温，
   也排除了这些名字（ADR-0001）。

## 3. 差异化校准（诚实红线，写简历/README 必须保持此口径）

- ❌ 禁说："原版没有修复闭环 / 没有纵向验证概念"
- ✅ 正确："原版有 finding-bound repair 流程与 later-validation 模型概念，
  但停留在人驱动与状态记录；我们提供无人值守执行、执行级复跑（replay_ok）
  与统计检验（bootstrap/CUSUM + 混杂否决）的机制化实现"
- 该口径的可证伪点都在自己代码里：T3.7（normal 拒 partial）、T5.2（replay_ok）、
  T5.7（假阳性仿真），面试追问时逐条可演示。

## 4. 被否决的备选与理由

| 备选 | 否决理由 |
|------|---------|
| 纯 Python 复刻原版 | 永远跟随；宿主适配数量战打不过官方；差异化塌缩 |
| 纯寄生宿主（无自带引擎） | 闭环主张塌掉；服务端无从聚合 |
| 通用 Agent trace 分析器 | 与 LangSmith/AgentOps 红海正面撞 |
| 原始会话全量上传 + 信任承诺 | 开发者会话含源码与私有路径，信任成本杀死冷启动 |
| 一期做 Inspector UI / 团队大盘 | 挤占三项深化预算；数据模型未跑通前聚合层是空中楼阁 |

## 5. 风险登记（与 PRD §10 对应）

- 宿主格式私有且会变（R1）→ 版本探测 + 显式降级，适配器子包隔离爆炸半径
- 小样本统计效力（R2）→ "证据不足"为合法输出，报告缺多少样本
- LLM 幻觉（R3）→ 三道闸（引用/基线/对抗），AGENTS §4.3 红线兜底
- 单人战线（R5）→ M2 前零 LLM 依赖 + 每里程碑独立可演示物
